# 看板模块（可选）

只有在配置里启用了看板、**且**用户提到 看板 / 待办清单 / 桌面小组件 / 小窗口 时才读这份。

## 它是什么

把档案根目录下的几个 Markdown，变成两个"不用打开 Codex 也能扫一眼"的东西：

1. **完整看板**（`看板.html`）—— 浏览器里打开，左侧文档树 + 右侧内容
2. **桌面小组件**（`_工具\小窗口.py`）—— 桌面角落常驻小窗，上半区「今日课程」、下半区「待办」

## 数据流

```text
待办清单.md（勾选会写回）─┐
                          ├─→ 生成看板.py ─→ 看板数据.json ─→ 小窗口.py ─→ 屏幕
课表.md ──────────────────┘         └─→ 看板.html
```

相关文件（相对档案根目录）：

```text
├── 待办清单.md                          ← 数据源（勾选会写回这里）
├── 看板.html                            ← 生成物
└── _工具\
    ├── 生成看板.py                      ← 读 md → 产出 看板.html + 看板数据.json
    ├── 小窗口.py                        ← 桌面小组件，读 看板数据.json
    ├── 看板数据.json                    ← 生成物
    └── 看板小程序_子会话Prompt.md        ← 专职对话的提示词
```

## 这个对话（大学助手）在这里只做一件事

- ✅ **保证数据源对得上**：比如"这周该做哪些"这类滚动待办，要和主台账的结论保持一致
- ❌ **不要改 `_工具\` 下的脚本**（`生成看板.py`、`小窗口.py`）——那是**「看板小程序维护」对话**的专属辖区，它有自己的一份提示词
- ❌ 不要手改 `看板.html` / `看板数据.json`——都是生成物，重跑脚本就覆盖了

## 先判断用户有没有这套

根目录下没有 `_工具\生成看板.py`，说明用户没搭看板 —— 直接忽略这个模块，**不要主动建议他去搭**。
